Walkthroughs API

One endpoint that returns every published walkthrough with its shareable link. Built for server-to-server use — n8n, a CRM, a listings feed.

Endpoint

GET https://lionrock-walkthrough.vercel.app/api/walkthroughs

Returns application/json. GET only — anything else returns 405.

Authentication

Send the API key as either header — both work identically, so pick whichever your tool makes easier. These are templates: replace YOUR_KEY with the key below (or use the ready-to-run command).

x-api-key: YOUR_KEY
Authorization: Bearer YOUR_KEY

API keys

Generate a key for each consumer, with an expiry to suit. Keys are stored as a hash — the plaintext is shown once, at creation, and can never be retrieved again. Revoking one takes effect immediately and doesn't affect the others.

Try it

Runs a real request from this page using the key above. Add filters below to try them out — see Filters.

Filters

All optional, all combinable. Add them to the URL as query parameters — the response echoes back which ones were applied.

ParameterExampleWhat it does
slug ?slug=unit-9 One specific property. Returns 404 if that slug doesn't exist, rather than an empty list.
type ?type=video Only that tab — video or interactive. Anything else is a 400.
search ?search=chicago Title, address, or slug contains the text. Case-insensitive.
hasIntro ?hasIntro=true Only properties that have (or don't have) an intro clip.
includeRooms ?includeRooms=false Drops the rooms array. Much smaller when you only need links — 21KB down to 3KB on the current data. roomCount is still included.
limit / offset ?limit=10&offset=20 Paging. matched in the response tells you the total before paging.

Combining them

# one property, links only — the smallest useful response
?slug=minnehaha-flats-unit-10&includeRooms=false

# every Chicago Ave unit in the Video tab
?type=video&search=chicago

# first 10 interactive walkthroughs
?type=interactive&limit=10

Counts in the response

FieldMeaning
countHow many are in this response, after every filter and paging.
matchedHow many matched the filters, before limit/offset.
totalHow many exist in all, before any filter.
filtersWhich filters were applied, or null if none.

Fields

FieldMeaning
titleUnit name as shown in the gallery.
addressStreet address, or null if none was entered.
slugURL-safe id. Follows the title — renaming a unit changes this, which breaks previously shared links.
typevideo or interactive — which tab it belongs to.
urlThe full shareable link. Built from the request host, so it is correct on any deployment.
pathSame link without the domain, if you prefer to build your own.
hasIntroWhether an intro clip plays before the first room.
roomCountNumber of playable rooms.
rooms[].videoDirect URL of the room's forward clip.

A property with no playable clip is left out entirely — the same rule the gallery uses, so this list always matches what people can actually open.

Status codes

CodeMeaning
200Success.
401Missing or wrong API key.
405Wrong method — only GET is allowed.
500WALKTHROUGH_API_KEY is not set on the deployment, or Supabase is not configured. The endpoint fails closed: it returns no data rather than serving it unprotected.
502Supabase itself returned an error.

Getting HTML back instead of JSON usually means the URL is pointing at a different site. Check it ends in .vercel.app and includes /api/walkthroughs.

JavaScript

const res = await fetch(
  'https://lionrock-walkthrough.vercel.app/api/walkthroughs',
  { headers: { 'x-api-key': process.env.WALKTHROUGH_API_KEY } }
);
const { walkthroughs } = await res.json();
walkthroughs.forEach((w) => console.log(w.title, w.url));

Setup

Keys live in the api_keys table, so supabase/migrations/007-api-keys.sql must be run once in the Supabase SQL editor. Until then this page can’t list or generate keys, and the endpoint returns 500 rather than serving data unprotected.

SUPABASE_URL and SUPABASE_ANON_KEY must also be set in Vercel → Project Settings → Environment Variables, then redeploy — Vercel only reads environment variables at build time, so saving alone changes nothing.

There is no longer a WALKTHROUGH_API_KEY environment variable. The database is the only source of truth: a key works only while its row exists, is unrevoked, and is unexpired.
